# F-05 경험 기록·회고 요구사항

## P0

| ID | 요구사항 | 이유 |
| --- | --- | --- |
| REC-01 | 사용자는 제품 하나 또는 현재 루틴에서 언제든 경험을 기록한다. | 의미 있는 순간을 7일까지 기다리게 하지 않는다. |
| REC-02 | 기록은 전반적 인상 `마음에 듦·아쉬움·모름`, 자유 원문, 선택 관찰 태그와 불편 여부를 분리한다. | 불편 없음만 성공으로 취급하지 않는다. |
| REC-03 | `현재 루틴`은 실제 사용 조합이고 `확인 중인 루틴`은 해당 조합의 사용감을 일정 기간 기록하는 별도 상태다. 확인이 끝나도 현재 루틴은 유지되며, 기록은 해당 루틴 버전과 작성 시각에 연결된다. | 실제 사용 여부와 관찰 진행 여부를 혼동하지 않고 경험의 조건을 보존한다. |
| REC-04 | AI 구조화 결과는 원문을 덮지 않고 원문에 없는 피부 상태·원인·선호를 만들지 않는다. | 개인 데이터의 출처를 보존한다. |
| REC-05 | 루틴 시작 7일째에 한 번 회고 행동을 노출하되 미응답을 결과로 추정하지 않는다. | 문제없을 때도 경험을 회수하는 기본 시점이다. |
| REC-06 | `모름`은 유효한 기록이며 사용을 연장하거나 결론을 강요하지 않는다. | 불확실한 경험을 왜곡하지 않는다. |
| REC-07 | 실제 사용이 비슷하고 불편 없음이 명시된 루틴은 사용자의 확인으로 비교 기준이 될 수 있다. 만족 여부와는 별개다. | Rescue 변경 비교를 위한 기준만 남긴다. |
| REC-08 | 불편이 포함되면 저장 완료 뒤 같은 AI 채팅에서 Rescue를 선택해 이어갈 수 있다. | 기록을 잃거나 같은 사실을 다시 입력하지 않는다. |
| REC-11 | 같은 제품·루틴의 확인 기간에는 기록을 여러 번 누적하되, 경험 상세의 진행 요약에는 가장 최근 기록 한 건의 상태만 보여준다. 홈의 현재 루틴 카드에는 기록 상태를 노출하지 않는다. | 원본 기록은 보존하면서 현재 상태를 빠르게 읽고, 홈의 핵심 행동은 가볍게 유지한다. |
| REC-12 | 피부 불편 여부는 `없음·있음·모름` 중 하나를 사용자가 직접 고르며, 미선택을 불편 없음으로 저장하지 않는다. | 답하지 않은 상태를 관찰 사실로 오해하지 않는다. |
