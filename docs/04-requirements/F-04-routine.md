# F-04 루틴·사용 맥락 요구사항

[Feature #160](https://github.com/skn-labs/app/issues/160)

## P0

| ID | 요구사항 | 이유 |
| --- | --- | --- |
| RTN-01 | 루틴은 제품·아침/저녁·순서·빈도를 한 사용기간의 불변 버전으로 저장하며 클렌징도 포함한다. | 경험이 생긴 조건을 나중에 복원한다. |
| RTN-02 | 제품 하나만으로도 사용 경험을 시작할 수 있고 루틴 전체 입력을 강제하지 않는다. | 짧은 제품 경험도 놓치지 않는다. |
| RTN-03 | 루틴을 바꾸면 과거 버전을 보존하고 새 ACTIVE 버전을 만든다. 과거 버전을 다시 활성화하지 않는다. | 변경 전후 경험이 섞이지 않게 한다. |
| RTN-04 | 내 화장품에 없는 제품은 등록 후 같은 루틴 편집안으로 돌아온다. | 추가 흐름에서 사용 맥락을 잃지 않는다. |
| RTN-05 | 새 ACTIVE 루틴은 경험 회고 due를 만들되 저장과 회고를 한 트랜잭션이나 AI 성공에 묶지 않는다. | AI 실패가 실제 사용 기록을 막지 않는다. |

## P1

| ID | 요구사항 | 이유 |
| --- | --- | --- |
| RTN-06 | AI는 제품 집합을 바꾸지 않는 순서·빈도 제안을 만들고 사용자가 적용한 경우에만 편집안에 반영한다. | 실제 사용 사실을 AI가 자동 결정하지 않는다. |
| RTN-07 | 제품별로 현재 조합에서 확인할 사용감·중복·정보 부족을 설명한다. | 루틴 입력의 즉시 가치를 높인다. |
| RTN-08 | 새 루틴은 AI 이름 제안과 무관하게 먼저 저장한다. AI는 저장된 제품·순서·시간·빈도만으로 이름을 제안하고, 사용자가 확인하거나 수정한 뒤 적용한다. 실패 시 구성 기반 기본 이름으로 같은 흐름을 마칠 수 있다. | 외부 호출 실패가 루틴 생성을 막거나 AI가 사용자 승인 없이 이름을 확정하지 않게 한다. |

### 루틴 이름 톤

- 이름은 제품 종류·순서·사용 시간·빈도에 실제로 있는 정보만 재료로 쓴다. 브랜드명·전체 제품명·성분명과 제품명에서 가져온 수식어는 이름에 넣지 않는다.
- SKN 이름은 브랜드명 같은 추상적 조어보다 실제 구성을 바로 이해할 수 있는 자연스러운 한국어 제목을 우선한다.
- 같은 종류의 제품 수, 마지막 단계, 다른 사용 빈도, 첫 단계와 마지막 단계 중 가장 기억하기 쉬운 특징 하나만 설명한다.
- `세럼 2개를 더한 저녁 루틴`, `선크림으로 마치는 아침 루틴`처럼 구성을 문장으로 요약하고, 특징이 약하면 `저녁에 쓰는 루틴`처럼 단순하게 남긴다.
- `레이어`, `리듬`, `페어`처럼 뜻을 다시 해석해야 하는 추상적 조어를 피한다.
- 피부 타입·성분·효능·안전·원인·적합성을 이름으로 추론하지 않는다.
- `완벽한`, `빛나는`, `프리미엄`, `맞춤`, `N단계`처럼 과장되거나 기계적으로 보이는 표현은 피한다. 같은 종류가 반복되는 특징을 설명할 때만 제품 종류의 개수를 쓴다.
