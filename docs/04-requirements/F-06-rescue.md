# F-06 AI Rescue 요구사항

## P0

| ID | 요구사항 | 이유 |
| --- | --- | --- |
| RSC-01 | 불편 경험에서 진입하거나 공통 AI 채팅에 불편함을 자유 문장으로 말하면, 같은 대화가 내부적으로 Rescue로 전환되고 진입 원문을 보존한 채 안전 확인부터 이어진다. AI 첫 화면에는 붉은 계열의 `피부가 불편해졌어요` 추천 질문을 제공한다. | Rescue를 별도 챗봇처럼 반복 입력시키거나 사용자가 기능 모드를 직접 고르게 하지 않는다. |
| RSC-02 | 이전 메시지를 지우지 않고 한 대화로 이어가며 입력창과 예상 답변 최대 3개를 유지한다. | 판단 과정과 사용자 정정을 보존한다. |
| RSC-03 | AI는 심한 변화, 발생 시점, 실제 사용과 함께 바뀐 것 중 필요한 정보만 한 번에 하나씩 묻고 모름을 허용한다. | 장문의 진단 설문과 AI 추정을 피한다. |
| RSC-04 | 서버는 비교 기준 루틴과 현재 루틴의 제품·시간대·순서·빈도 차이를 계산하고 사용자가 수정한다. | AI 기억보다 저장된 사실에서 시작한다. |
| RSC-05 | 확인 순서는 변경 시점·함께 바뀐 항목·관련 과거 경험으로 만들고, 변경 제품의 공식정보·공공기관·연구 자료를 API 내부 검색으로 보조한다. 지지·반대·정보 부족과 문장별 출처를 표시하며 원인·범인·확률로 표현하지 않는다. | 행동 순서를 진단과 구분한다. |
| RSC-06 | 보유 제품 안에서 유지·제외가 명확한 보수적 다음 루틴 하나를 제안한다. | 분석을 다음 행동으로 연결한다. |
| RSC-07 | 사용자가 승인한 경우에만 기준 ACTIVE가 여전히 같은지 확인하고 새 독립 루틴을 만든다. | 오래된 AI 제안이 최신 상태를 덮지 않는다. |
| RSC-08 | 심하거나 빠르게 악화된다는 사용자 표현이 있으면 제품 순위와 루틴 제안을 중단한다. | 의료 판단 경계를 지킨다. |

## P1

| RSC-09 | 사용자는 제안을 적용하지 않고 경험과 대화만 저장한다. | AI를 따르지 않은 행동도 개인 이력이다. |
| RSC-10 | 반복 Rescue는 과거 case를 덮지 않고 관련 경험으로 참조한다. | 반복된 불편 맥락을 다음 확인에 쓴다. |
