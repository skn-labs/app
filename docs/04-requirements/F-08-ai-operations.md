# F-08 AI·보안·운영 요구사항

[Feature #164](https://github.com/skn-labs/app/issues/164)

## P0

| ID | 요구사항 | 이유 |
| --- | --- | --- |
| AI-01 | OpenAI Responses API는 자연어 경험 구조화, 관련 기록 연결, 최소 추가 질문, 패턴·탐색·Rescue 설명과 `web_search`를 맡는다. 제품·성분·사용법 등 외부 사실은 모델 기억이 아니라 같은 API 호출 안의 검색 결과에서만 가져온다. | 정적 enum과 오래된 모델 기억으로 코덕의 표현·최신 제품 정보를 채우지 않는다. |
| AI-02 | AI 출력은 원본 관찰, AI 해석, 외부 사실과 불확실성을 구분하는 schema를 따르며, 외부 사실은 OpenAI `url_citation`으로 문장별 출처를 가진다. | AI 문장을 개인 사실이나 출처 확인 사실로 오인하지 않는다. |
| AI-03 | 서버는 사용자 권한, 실제 제품·루틴·경험 ID, 상태 전이, 개인 근거 참조와 인용 URL을 검증한다. HTTPS 인용만 저장하고 P1~P4 분류와 메시지별 출처 순서를 고정한다. | AI가 시스템 사실이나 가짜 출처를 만들지 못하게 한다. |
| AI-04 | AI가 실패해도 제품·루틴·경험 원문·사용자 메시지는 남는다. 일반·제품·추천·패턴·Rescue는 각각 저장된 도메인 데이터로 직접 답하며 일반 장애 문구만 반환하지 않는다. | 외부 장애가 개인 기록과 핵심 행동을 막지 않게 한다. |
| AI-07 | 모든 AI 대화와 웹 검색의 기본 모델은 `gpt-5.6-terra`다. 429·5xx·timeout은 `Retry-After`를 우선해 한 번 재시도하고, 끝내 실패하면 AI-04의 모드별 서버 답변을 반환한다. | 모델 구성을 단순하게 유지하면서 핵심 질문의 종착점을 보장한다. |
| SEC-01 | 모든 개인 자식 데이터는 복합 FK와 서비스 검사로 같은 사용자 부모만 참조한다. | API 실수로도 교차 사용자 연결을 저장하지 않는다. |
| SEC-02 | 사용자가 요청한 질문에 필요한 기록만 AI 공급자에게 보내고 메모·이미지 원문을 임의로 포함하지 않는다. | 최소 전송 원칙을 지킨다. |
| OPS-01 | 해커톤 구현의 SQLite schema 원본은 `schema.sql` 하나로 두고 FK·CHECK·UNIQUE를 켠다. 기존 사용자 데이터를 운영하기 시작할 때 Flyway를 도입한다. | 지금은 계약을 단순하게 유지하고, 운영 데이터가 생긴 뒤에는 안전하게 승격한다. |
| OPS-02 | AI·Object Storage 호출은 DB 쓰기 트랜잭션 밖에서 수행한다. | SQLite 쓰기 잠금을 오래 잡지 않는다. |
| OPS-03 | 한 번만 반영할 쓰기는 멱등 키를 쓰고 AI 제안 적용 전 기준 버전을 비교한다. | 중복 기록과 오래된 제안 적용을 막는다. |
