# 요구사항

요구사항은 SKN이 지켜야 할 사용자 결과와 시스템 의무다. 사용자의 현재 요청과 이 디렉터리의 문서가 흐름·분기·오류·완료 조건의 기준이며 GitHub 이슈는 과거 작업 이력으로만 본다.

## 우선순위

### P0 · 개인 경험 순환

```text
제품 탐색 → 실제 사용 맥락 → 경험 기록
→ 원본 기반 패턴 → 다음 제품 탐색
                     ↘ 불편하면 AI Rescue
```

P0는 이 순환을 실제 사용자 데이터로 한 번 완주하고, 다른 사용자의 기록이 섞이지 않으며, AI 실패에도 원본이 남는 범위다.

### P1 · 신뢰와 회수율

외부 근거 snapshot, 반복 패턴 재계산, 제품 상세 이력, 알림, 반복 Rescue와 AI 비동기 운영을 추가한다.

### P2 · 입력·구매 편의

영수증 OCR, 가격·판매처, 찜, 광범위한 카탈로그와 범용 온보딩을 추가한다.

## 결정 기준

- 기록을 많이 받는 것보다 한 경험이 다음 탐색에 실제로 재사용되는 것을 우선한다.
- 7일과 비교 기준 루틴은 패턴 발견을 돕는 수단이지 제품의 목적이 아니다.
- 기능을 추가할 때 `경험을 남김`, `과거와 연결`, `다음 탐색에 재사용` 중 어디를 개선하는지 설명하지 못하면 P0에 넣지 않는다.
- 피부 상태를 정적 enum으로 완전히 통제하지 않는다. 원문과 최소 구조화 필드를 함께 저장한다.
