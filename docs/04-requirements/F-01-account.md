# F-01 계정·데이터 경계 요구사항

## P0

| ID | 요구사항 | 이유 |
| --- | --- | --- |
| ACC-01 | 사용자는 아이디와 비밀번호로 가입·로그인하고 자기 제품·루틴·경험·패턴·대화에만 접근한다. | 개인 기록이 섞이면 모든 패턴과 탐색 결과가 무효다. |
| ACC-02 | 사용자는 계정과 연결 데이터를 영구 삭제할 수 있다. | 민감할 수 있는 피부·사용 경험에 필요한 통제다. |
| ACC-03 | 가입 후 온보딩은 `연령대 → 성별 → 피부 타입 → 최근 피부 상태 → 고민 → 선호 사용감 → 피하고 싶은 항목 → 새 제품 시도 빈도` 순서로 자기보고 피부 프로필을 받는다. 마지막 저장이 성공하면 완료 화면을 보여주고, 사용자가 직접 확인한 뒤 메인으로 이동한다. 완료 상태는 재접속 후에도 유지한다. | 첫 개인화 흐름을 실제 계정 데이터와 연결한다. |
| ACC-04 | 새 계정을 만든 직후에는 첫 프로필 질문 전에 브랜드 웰컴 시퀀스를 한 번 보여준다. 로그인·진행 중 재접속에서는 반복하지 않고, 동작 줄이기 설정이나 모션 실패가 있어도 첫 질문으로 이동할 수 있어야 한다. | 입력부터 요구하기 전에 제품의 목적을 짧게 이해시키되 반복 진입과 모션이 온보딩을 방해하지 않게 한다. |
| ACC-05 | 가입·로그인·데모 진입은 발급 후 30일에 절대 만료되는 단일 액세스 토큰을 시작한다. 토큰은 `HttpOnly`·`SameSite=Lax` 쿠키로만 전달하고 서버에는 hash만 저장한다. 리프레시 토큰은 두지 않으며 로그아웃·계정 삭제 시 현재 토큰을 즉시 폐기한다. | 서버 재시작과 무관하게 로그인 상태를 유지하면서 브라우저 스크립트 노출과 로그아웃 후 재사용을 막는다. |

## P2

| ID | 요구사항 | 이유 |
| --- | --- | --- |
| ONB-01 | 사용자는 온보딩에서 저장한 자기보고 피부 프로필을 이후 조회·수정할 수 있다. 프로필은 사용자가 직접 고른 현재 맥락이며 AI가 추론한 진단이나 영구 판정으로 취급하지 않는다. | 시간이 지나며 달라지는 상태와 선호를 사용자가 통제할 수 있어야 한다. |
| MEM-01 | 사용자는 AI가 보존한 범용 맥락을 조회·수정·삭제한다. | 범용 기억 기능을 실제로 도입할 때 필요한 통제다. |

8단계 결과는 `user_skin_profile`에 한 묶음으로 저장한다. 고민과 선호 사용감은 하나 이상 선택해야 하고, 피하고 싶은 항목과 직접 입력은 비워도 된다. `잘 모르겠어요`는 피부 타입의 유효한 응답이다. 사용감과 기피 항목은 기존 `/api/v1/me/preferences`에도 동기화하며, 전체 프로필은 `/api/v1/me/skin-profile`로 조회·수정한다.

> 프로필은 사용자의 자기보고 값이다. AI가 기록에서 연령·성별·피부 타입을 추론하거나, 한 번의 입력을 원인·진단·영구 선호로 확정하지 않는다.
